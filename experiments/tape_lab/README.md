# TAPE LAB — первый прототип аудиоленты DECK

Это отдельная экспериментальная прошивка, не обновление полного DECK.
Одна настоящая аудиопетля **до 2,97 секунды, моно 22,05 кГц**, наложение и отмена последнего дубля.
На клавишах — простой синусный синтезатор для проверки. Звук петли хранится в RAM, без повторного синтеза нот.
При выключении петля пропадает. Прошивка не сохраняет её во флеш.

## Попробовать

1. Установи `tape-lab.fwsc` через `install-tape-lab.bat`. Полный DECK временно заменится этим тестовым приложением.
   Для возврата установи прежний `deck-overworld.fwsc` обычным установщиком.
2. Нажми REC и сыграй короткую фразу. Ещё раз REC — закончить запись и запустить петлю.
   На пределе 2,97 секунды она замкнётся автоматически. Отпусти клавиши немного до завершения, чтобы записался хвост.
3. REC во время воспроизведения — подготовить наложение. Надпись DUB NEXT LOOP: оно начнётся с начала следующего круга.
   Сыграй второй голос. Через один полный круг запись автоматически закончится.
4. EDIT — отменить последний дубль; EDIT ещё раз — вернуть его. Доступно после завершения прохода.
5. PLAY — остановить/продолжить. Во время наложения остановка ждёт конца прохода, чтобы undo оставался целым.
6. HOME + SAVE — очистить петлю, когда запись не идёт. OCT− / OCT+ — октава тестового синта.

Индикаторы: CPU — фактический замер рендера на устройстве, XRUN — пропущенные аудиосроки,
MS — длина петли, CLIP — число ограниченных записываемых отсчётов. При росте CLIP убавь число одновременно играемых нот.
MASTER меняет громкость прослушивания, не уровень записи. USB-аудио и MIDI-вход в этом прототипе не включены.

Установщик требует Python и пакеты mido/python-rtmidi. Устройство автоматически не прошивалось.

## Что проверено

- Хост-тест: запись до границы буфера, наложение, точные undo/redo, отсутствие обратной записи самой петли,
  завершение прохода при STOP, ограничение амплитуды, защитные значения за пределами буферов.
- Граница произвольной петли смягчается короткими затуханиями по 64 отсчёта (~2,9 мс с каждой стороны).
  Это устраняет резкий скачок, но даёт короткий спад громкости на стыке. Это ещё не бесшовный tape-splice.
- Хост-сценарий нажимает реальные кнопки приложения, пишет и проигрывает петлю, делает дубль и undo,
  останавливает и очищает. Все проверки проходят, записей хранилища — 0.
- Собрано для FM-1: образ 71364 байта; RAM 14688/98304, pool 331268/344064.
- На настоящем устройстве ещё не проверено; хост-скорость не равна загрузке CPU FM-1.

`tape-lab-demo.wav`: запись одного тона → воспроизведение → второй тон поверх → смесь → undo → redo →
нулевой дубль → остановка. Это технический пример алгоритма, не музыкальный пресет.

## Что выяснилось про длинную ленту

В текущей базе ожидается флеш 1 МиБ (`base/device/main_fm1.c`, JEDEC 0x856014).
Приложению доступны 292 КиБ data-области; проекты и пары секторов пресетов/калибровки уже занимают 160 КиБ.
В незанятых промежутках остаётся 132 КиБ, причём фрагментами: максимум около 1,53 секунды PCM16 mono 44,1 кГц
или 0,77 секунды stereo. Это верхняя оценка без заголовков и резервирования для безопасного обновления.
Эти промежутки прототип не использует. Область загрузчика и проектов не переразмечалась.

Драйвер явно глушит звук при стирании сектора. Поэтому непрерывная запись в этот флеш с нынешним драйвером
не подходит для многодорожечной ленты. Это вывод по исходникам; скорость физической флеш-памяти здесь не измерялась.
`storage-audit.json` содержит карту и расчёт, `tools/audit_tape_storage.py` воспроизводит его без доступа к устройству.

Практический путь: сохранить нотные дорожки полного DECK; использовать небольшие RAM-фрагменты для ресэмплинга.
Длинные аудиодорожки потребуют внешнего хранилища/компьютера или аппаратной доработки.
Этот отдельный тест занимает память, которую в полном DECK занимают движки и эффекты: напрямую добавить его буферы туда нельзя.

## Сборка

`python base/tools/build.py experiments/tape_lab` — устройство.
`python base/tools/build.py experiments/tape_lab --host` — симулятор.
`tape-lab_host experiments/tape_lab/scenario.txt OUTDIR` — сценарий и снимок экрана.
`gcc -O2 experiments/tape_lab/test_loop.c experiments/tape_lab/loop.c -lm -o tape_test` — тест ядра.
На Windows используется w64devkit; пути JieLi/SDK задаются как для основного DECK.
